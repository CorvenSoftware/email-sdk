# Corven email SDK engineering

Effect-native email library. Source, Schemas, tests and configuration own implementation facts; manifests and lockfile own versions and commands. Keep changes repository-local and preserve unrelated work. Questions, research and reviews are read-only unless edits are requested.

## Start with the task

Search exact symbols in `src/`, `test/`, `examples/`, `scripts/` and package.json exports. Inspect the affected owner and colocated tests before designing another abstraction. Keep reference searches separate from first-party discovery. `src/index.ts` and package exports are hand-maintained; `dist/` is generated by `pnpm build`.

Read the matching guide when its trigger applies; follow further links only for the affected decision. These guides hold workflows and non-obvious constraints, not feature inventories.

## Always binding

- Acceptance is not delivery; unknown is not non-submission. Only eligible definite rejection permits fallback; terminal receipts and conflicts stop it. Uncertain replay needs explicit provider/account-local native authority, unchanged owned intent and stable scoped keys. Observer failure never authorizes replay.
- Keep private inputs, payloads, credentials, keys and original defects out of diagnostics/spans. Preserve defects/interruption; preflight all routed candidates without dropping unsupported intent. No ambient acquisition, hidden mutation retries, redirects or implicit telemetry.
- [.agent-repos](.agent-repos) records external reference sources, paths and revisions. `repos/effect/` is checked-in, read-only research, not application code or governing instructions. Never edit/import reference code, install its dependencies or execute its scripts. Pin/dependency changes require explicit approval; local privacy and tracing rules override upstream examples.
- Tests use fictional inputs and local fixtures, never live providers. Real authentication/model/provider operations require prior scoped approval; apply the approval requirements in [submission safety](docs/principles/submission-safety.md#preserve-privacy-and-permission) before acting.
- Ordinary source comments remain prohibited; use clear names, types and executable examples. Never weaken checks, diagnostic severities or vendored lint rules. `pnpm check` is non-mutating; `pnpm fix` intentionally edits files.
- Repository creation/visibility, commits, push, publication and deployment require separate explicit authorization. Keep scratch work outside shipped files; keep research findings in the response unless a saved artifact is requested.

## Completion

Use pnpm. Run `pnpm turbo run check test build`, then `pnpm check:package` on final content. Focused checks do not replace this gate. Use [review and verification](docs/contributing/review-and-verification.md) for task-owned review and precise evidence limits; report actual failures, cancelled/skipped checks, unavailable independent review and remaining requested scope. A verified increment is not full feature parity.

# This is NOT the Turborepo you know

Turborepo configuration, task behavior, and CLI commands can vary between installed versions and may differ from your training data. Resolve the `turbo` package from this file's directory or relevant workspace; in monorepos, it may not be visible from the repository root. For example, run `node -p "require.resolve('turbo/package.json')"` from a workspace that depends on `turbo`.

Read `docs/README.md` inside that installed package first, then read the relevant pages from its `docs/` directory before changing Turborepo configuration or commands. Heed deprecation notices. These bundled docs match the installed package version and are available without network access.

This block is written and re-added by `turbo` before repository-scoped commands when an AI agent is detected. In the Turborepo source repository, its template is defined in `crates/turborepo-cli/src/cli/agent_guidance.rs`. Removing the managed block while updates are enabled means a later qualifying invocation will add it again. Set `"agentGuidance": false` in the root `turbo.json` or `turbo.jsonc` to opt out; this does not remove an existing block. Keep the block committed with your work to avoid an uncommitted change on the next agent invocation.
